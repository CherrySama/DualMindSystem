# 持续局部意图与动作选择闭环

本轮按用户确认的方案实现可对照的 JEV 两层选择：首次选择局部意图，动作请求读取已选意图；Runtime 保存意图并在新观测后检查完成、失效和无进展。当前任务计划仍给定，没有接入 LLM 慢脑。

## 契约与职责

`LocalIntentCandidateV1` 描述局部目标、相关参考、允许动作、持续要求、几何来源及进展类型。`LocalIntentChoiceV1` 只保存 JEV 选择的候选 ID 和当前状态/动作 epoch/能力/阶段绑定，模型不能直接生成未经登记的坐标。`LocalIntentExecutionV1` 保存该次选择、局部状态、观测误差、历史最好误差和无改善计数。`LocalIntentContextV1` 绑定单次新快照；所有记录均不可变。

候选源于通用能力契约及公开几何，不读取最终隐藏验收或额外接触力。推动接近针对观测 footprint 的每条非退化边计算外侧中点候选，偏移量使用已有 precontact_clearance 配置；只检查点在公开支撑边界内及到 footprint 的距离。候选不按路线优劣排序，JEV 自选边。选定边在水平接近、高度调整及接触之间保留，失效或显式局部重规划时重新选择。边中点候选是有限采样，不代表覆盖全部可行接近位置。

Runtime 没有替 JEV 选择动作或预设推开方向。候选的轴限制来自局部意图语义：水平对齐使用水平动作，高度调整使用垂直动作；抓取高度候选沿用已有 XY 对齐前提。选定目标的坐标误差与符号是公开几何关系，不是由代码替模型选择的动作。

## 两层输入

意图选择使用 `JEVDecisionContextV1`，包含子任务目标、阶段条件、全部候选、相关几何及先前意图反馈。

动作选择使用 `JEVLocalActionContextV1`：

- 已选局部意图、目标减实测 TCP 的修正、误差符号、局部距离及容差；
- 当前机器人/夹爪反馈、主体与相关依赖几何、其他物体；
- 实际动作结果、意图状态及进展历史、观测编号和证据来源；
- 局部动作手柄，以及各几何动作按命令步长计算的预期局部误差和误差变化。

预期变化显式标为 `bounded_command_geometry`、`is_observed: false`。它只计算公开目标减 TCP 在假定步长后的几何变化，不推断接触力、碰撞或真实执行效果。所有选项仍交给 JEV 选择，Runtime 不取最大进展项代执行。

几何对齐动作不再携带整个任务、其他意图候选或最终区域目标。关系、接触、释放等没有统一点修正的意图仍读取必要的当前阶段条件与几何；只有当前局部条件需要目标关系时才携带关系定义。未知修正为 null，不替换成零。

首次意图和动作请求使用同一状态绑定；意图有效时只更新动作请求，不再次调用意图选择。每次动作决定仍绑定新快照。两层输出均保留原有响应模型、选项、概率一致性校验。Runtime 在执行前再核对状态编号与动作 epoch，并检查动作属于选定意图。接触、关系及释放的连续进展度量尚未完整实现，不能把 Boolean 未改变直接当作没有物理进展。

## 意图生命周期与局部重规划

几何意图的局部完成由当前 TCP 到选定目标的距离及原具名容差判断；它不宣布能力或任务完成。最终阶段条件与双重仿真验收保持原有职责。

新观测发现参考几何失去可观测性、参考移动超过有效范围或持续没有新的最佳几何误差时，使意图失效。进展只比较执行后实际观测，每个动作 epoch 只计一次。允许短期误差增加，不要求每一步所有条件同时下降。

XY 点对齐提议沿用通用执行前投影进展审查：不满足既有进展要求的动作会被拒绝，不由 Runtime 换成另一个动作。这只支持局部点对齐；需要先远离目标的绕行不能靠此审查获得完整路径证明，当前也没有实现路径规划器。

本轮在线抓取曾暴露并修复两个实现问题：Runtime 允许动作变为垂直动作时，不能把原 XY 目标误判为不可观测；执行后反馈必须对照该动作原先绑定的目标，而不是后来选中的新意图。几何有效性与当前动作权限现在分别检查，反馈保留原点目标。这里的实测误差是 TCP 到原选定点的距离，当前参考是否仍然有效另由意图管理检查，不能把它等同于当前物体对齐成功。

JEV 动作选择还可输出 `replan_local_intent`：显式请求重新选择局部意图，不产生机器人动作，不重置场景。这为调整高度转释放等语义变化提供合法出口，避免有效意图永远锁住动作层。该请求仍要通过原快照绑定校验。

配置 `configs/local_intent_v1.yaml` 单独保存试验值：最小新改善 0.0005 米、最多 6 个动作没有新最佳值、最多 3 次局部重规划、参考最大移动 0.015 米。这些是意图有效性试验参数，不是任务成功门槛，尚未针对现实噪声标定。局部重规划达到额度时报告需要上层重规划；当前没有慢脑消费者，不能宣称已经实现慢脑恢复。现有能力恢复机制及最多五次实际恢复限制保留，局部重选不计成实际能力重置。

## 使用与限制

`scripts/run_v1.py --jev-stages 1` 使用原单层选择，`--jev-stages 2` 启用本轮试验模式；批量入口传递同一设置并写入 manifest，单回合 result 也记录模式。默认仍为单层，避免将尚未证实可靠的模式直接设为默认。

全量自动化检查 131 项通过，其中局部意图检查 23 项，覆盖候选边、两层状态绑定、有效意图复用、几何修正刷新、局部完成和阶段完成分离、无进展计数、未知观测、参考移动、显式重规划、放置与释放意图区分、非法选择、实际 Runtime 循环连接、动作权限切换后的 XY 完成及原目标反馈绑定。这是契约和连接证据，不能当作在线任务可靠性证明。

以下信息边界仍未完成：模拟接触参与当前抓持/支撑估计；全工具占据、机械臂路径检查、现实视觉置信度、接触动作超时分类及部分能力恢复出口。候选的 `path_verified` 为 false，点在支撑区域内不等于机械臂或工具的整条路径安全。现实机械臂在网络请求期间不会自动冻结，本轮同步 MuJoCo 诊断不验证异步视觉延迟或真实执行前状态刷新。

慢脑未来应依据当前视觉和机器人反馈给出目标绑定与能力组合，并读取带证据的失败/重规划请求；眼睛与状态估计持续更新观测。可观测性不足不能由慢脑想象补齐，电机受阻也不能直接等同于抓持成功。本轮没有添加力估计器、模拟接触旁路、固定动作程序或场景路线。

### 尚未解决的架构问题

1. **接触阶段仍退回粗粒度表达。** 几何对齐意图有明确目标和连续误差；`establish_push_contact` 仍为阶段 Boolean 契约，没有对应选定侧面和工具形状的接触几何误差，也没有连续进展量。日志确认所选边保留、TCP 从边外接近，但接触阶段多次沿 X 移动，接触条件一直未满足。不能仅凭这些日志把失败归因为模型或物理，尚需区分工具接触几何、输入表达与执行可行性。
2. **局部重规划出口缺少有内容的失败反馈。** 抓取闭合阶段的意图、允许动作和实测夹爪开度均已传入；JEV 仍连续请求重规划。当前输出只有重规划选项，原因是主机统一文字，没有模型提供的具体阻塞依据；重复重选相同意图消耗额度，尚无慢脑接收并改变条件。不能用强制 GRIPPER_CLOSE 掩盖这一问题。
3. **接触中的动作仍按自由空间位置收敛验收。** 按压 DOWN 命令 10 毫米，实测 TCP 下降约 6.84 毫米、按钮行程约 6.87 毫米，执行器在位置误差未达 2 毫米时超时。代码确认接触动作与自由空间动作共享平移成功标准，但尚未确认未收敛由弹簧负载、姿态约束还是控制器造成。不能直接加大时限、放宽误差或把受阻宣布为按压成功。
4. **现实信息边界仍有缺口。** 抓持、接触和支撑仍带模拟接触证据来源，尚不能在只有 RGB-D 与机器人反馈的硬件上直接等价使用。实测位置变化、视觉关系及未来受阻估计应分开提供；无进展与受阻也不能直接变成力估计。

### 选择、执行和阶段判断的区别

- 单层抓取最后一次对齐请求中，目标修正为 X +4.263 毫米、Y -13.136 毫米。按原 10 毫米步长，RIGHT 的预计 XY 改善约 8.518 毫米，FORWARD 会使误差增加约 0.524 毫米；JEV 选择 FORWARD，Runtime 拒绝。因此该次失败发生在动作选择，不能说目标方向没有传入或 Runtime 把有效动作拦住。
- 单层按压最后一次对齐请求中，RIGHT 的预计改善约 9.612 毫米，JEV 选择 FORWARD，其预计改善约 0.474 毫米，低于原通用 0.5 毫米阈值而被拒绝。当时存在可接受的更大改善动作，不能把停止归因于所有动作均被审查封死。实际输入存在不代表 JEV 能稳定使用。
- 两层推动进入接触阶段时，所选意图是 `establish_push_contact`，`correction_robot_base_m` 为 null，`action_evaluations` 为空，只沿用阶段条件、原始物体几何和先前选定侧面。公开输入没有工具接触面的几何模型；当前粗粒度意图与工具相对物体接触几何之间缺少对应。这是已确认的信息表达缺口，尚未证明它是该回合失败的唯一原因。
