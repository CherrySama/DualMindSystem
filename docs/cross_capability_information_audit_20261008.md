## 两处确认的共同转换损失

### 交互解释被覆盖

`policies/jev.py` 基础请求为抓取探测、释放等阶段提供机制说明。两层分支在构建动作输入后直接替换 `instructions.rules`，改为主要解释 `tcp_xy`、`tcp_z` 和 `contact_geometry` 的通用规则。

这是实际的信息转换损失，不等于数据字段全丢失，也尚未证明某次决策失败正由它导致。现有单层释放测试验证了单层请求，并未保证这段解释经两层转换后仍在。

修复时不能简单拼接全部旧规则：完整输入中的 `motion_error_role/goal_delta` 在动作投影中未必存在，最终目标侧面选择属于意图层。应把交互机制解释与局部执行边界分开，按同一能力阶段复用；动作层继续受已选意图和允许动作约束，不重新选择策略或宣告完成。

### 前后观测被裁掉

Runtime `decision_feedback()` 在同一能力实例、阶段和合同，且上一动作编号与最近动作起点匹配时，保存 `previous_measurements`、`previous_state_id`、`previous_action_epoch`。完整输入保留这些字段，动作投影却无条件删除 `previous_measurements`，只留下旧编号。

不能说动作层没有任何历史：`recent_action` 仍有命令/实测 TCP 位移与状态；点对齐的 `decision_feedback` 有实测前后误差，意图执行记录有最佳度量/无进展计数，阶段验收有稳定次数。它们不能普遍替代主体或任务测量的前后变化。

也不能直接恢复前值后称之为可靠实测进展：当前 `PhaseFeedbackV1` 没有携带前一观测的完整时间/有效性依据和观测编号。恢复历史需补齐这部分来源，确保同一主体、目标、阶段和动作边界；未知、失效或不一致的前后值不得计算有效差值。布尔关系前后均为 false 时，仍无法推导连续距离变化。

## 支持不均衡与真实丢失应分开

`local_intent_metric_v1()` 只为点 XY/Z 与接触几何提供连续度量，`phase_contract` 返回 None 是明确的设计边界。很多阶段已经提供原始观察与关系语义；不能因为度量为 None 就声称整个任务信息缺失。

目前空预测列表未显式区分“此处没有动作后果实现”“证据不足”“此阶段不需要预测”。后续可明确支持范围，但不能为统一外观而给每个动作编造分数、把未知填零、把主体位移等同工具命令，或把固定主体下的预测相交当作真实推动违规。

当前模板/投影确实偏重点接近表达，但没有证据表明统一 schema 本身不可行，也没有发现任务对象坐标被固定为某一场景常量。适用的关系、来源与阶段依赖应按交互机制组织，不按十二个任务名称分别打补丁。

## 建议下一轮共同修复，待用户确认

优先修复已发生的信息转换损失，范围为两项：

1. 将阶段交互语义与局部执行约束分开，两个请求层复用适用的机制解释，避免覆盖。约束仍限定已接受意图、现有允许动作与 Runtime 验收权。
2. 补齐前一观测的身份、时间/有效性依据，传递同一作用域的前后测量。历史只记录一次；无法支持比较时明确未知，不增加动作评分或新验收门槛。

验收以五能力投影、抓取探测/释放语义保留、跨主体/目标/阶段与过期前值反例、点意图的局部权限、请求规模及保存断点对照为主。之后再分别补连续关系进展、推动当前接触关系、视觉退化与执行控制。现有场景、完成判据、阈值和恢复额度保持原配置；共同转换修复不能被描述为解决全部失败。
