# 第一轮：Runtime 正确性与阶段条件一致性

日期：2026-10-04。范围限于分类/清理终检、接触与抓持估计、阶段条件核对。第一轮完成后停止，后续轮次另行推进。

原十二任务批次已经执行：双重验收通过 2/12，十项失败。本轮没有新增完整任务回合，也没有调用 JEV，不能据此更新任务成功率。

## 已修复的具体问题

### 分类和清理缺少全部物体的最终复核

两类 Runtime 原先继承共享的默认任务终检；能力程序结束即可通过，没有重新核对早先完成的物体是否仍满足目标。因此，多物体操作中早先物体失效可能被遗漏。

现在从原 TaskPlan 的 `initial_binding.track_ids` 提取全部物体及其目标，在最终新公开观测中逐个检查 `IN_REGION`。物体不可见、轮廓未知、目标边界未知、视觉过期或关系不成立，均不通过。阶段验收与任务终检复用同一个 verifier 实例。

新增 `task_completion_verification` 事件，记录状态 ID、观测 ID、通过与否和具体失效绑定。隐藏 MuJoCo 验收仍独立进行。

对原批次保存的最终状态重评：

| 任务 | 原 Runtime 判定 | 新终检 | 原公开观测中的失效绑定 |
| --- | --- | --- | --- |
| clear | 通过 | 不通过 | `block_1 -> storage_region`，IN_REGION 不为 true |
| sort | 通过 | 不通过 | `block_1 -> red_region`，IN_REGION 不为 true |

这证明新终检能拒绝已有记录中的两项误报；没有证明物体搬运成功率提高，也没有重新执行原回合。

### 双指接触、推动接触与候选抓持混淆

原状态构建逻辑在双指接触时直接报告 `CANDIDATE_HELD`，推动阶段同时可能报告 `PUSH_CONTACT`，而推动验收要求 `NOT_HELD`。这是可由人工状态复现的内部矛盾；现有历史证据不足以把它认定为此前推动失败的直接原因。

现在候选抓持必须同时具备双指接触、闭合命令和开度受阻。单纯接触不再自动成为抓持候选。推动/按压中若确有夹持证据，也保留候选抓持并拒绝当作正常推动，避免仅靠任务类型排除误夹。确认 `HELD` 仍需原有抬升、物体视觉跟随和稳定证据；没有降低门槛。

该估计仍依赖标明来源的 MuJoCo 接触反馈，不能视为真机接触估计已完成。

### 按压和抓取探测的阶段漏项

- 按压阶段文字要求保持目标点 XY 对齐，但实际完成条件只检查按钮目标与接触。现在验收和 JEV 条件列表同时检查现有 `press_point_xy_tolerance_m`；误差计算复用同一函数。
- 抓取探测曾可能出现条件列表全部满足、实际验收因接触丢失拒绝。现在条件列表增加候选抓持，验收使用同一候选判断；抓持未知时保持待验证。
- 搬运净空的说明改为实际公式采用的高度参考：平面放置使用源/目标支撑高度较大值，入容器使用源支撑/容器开口高度较大值。计算公式及阈值未改。

## 本轮结论与未处理项

当前可以确认：框架存在真实的终检误报和内部条件漏项。十项任务失败不能统一归为 JEV 不理解任务，也不能统一归为 Runtime 拒绝错误。单层对齐的无进展拒绝仍有依据；本轮没有改变这些进展检查。

本轮修复提高判定与反馈的一致性，尚未证明任务更容易完成。发现早先物体失效后，现有恢复仍只重启当前/最后物体，尚不能自动回到任意失效物体。

以下留给后续轮次：工具接触面与物体侧面的几何表达、低位跨物体接近与全路径避障、释放前关系的持续保护、部分阶段支撑约束的逐动作保护、执行器下降超时的控制核查，以及失效物体的恢复选择。此前两层抓取旧回合不闭合的原因仍未锁定，九次决策重放仍不能作为九次抓取成功。

下一轮应先围绕接近与接触几何建立可复现检查，再决定是否修改动作空间和接触接口。本轮没有启动该项工作。
