# JEV 子任务输入与阶段反馈修复

本轮实现用户确认的设计：固定子任务定义复用，动态观测和执行反馈更新，每次决策仍绑定新的状态快照。范围是五种通用能力的输入语义及对应阶段验收连接；没有加入慢脑模型、力估计模型、任务专用动作程序，也没有修改 XML、物体尺寸、控制增益或最终验收门槛。

## 固定定义与动态状态

`planning/phase_definitions.py` 按现有具名完成契约描述二十个阶段的目标、运动主体、相关轴、持续要求及配置引用。最终目标另有关系解释，例如 LEFT_OF 按机器人基坐标系 +Y 和整个 footprint 的间距表达；CLEAR_OF_REGION 按完全分离及净间距表达。定义没有推动方向、唯一接触边、轨迹或动作次数。

绑定对象、源支撑、目标及关系后得到不可变 `BoundSubtaskDefinitionV1`，按能力实例和绑定内容缓存，最多保留 256 项。缓存不保存动态位置或反馈，缓存淘汰只影响复用开销。慢脑未来可以生成这些绑定，当前仍使用给定 TaskPlan。

每次 `JEVDecisionContextV1` 包含：

- `subtask_definition`：固定绑定、最终关系及阶段/完成契约索引。
- `phase`：当前阶段定义、实际配置数值、条件的观测值/比较关系/要求/容差/是否满足、刚刚发生的验收结果及具名观测量。
- `phase.measurement_definitions`：观测量的语义与计算公式，明确区分目标减当前的有符号修正、当前距离、绝对误差和布尔证据。例如推动高度修正为源支撑高度加配置工具高度减实测 TCP 高度，负值表示 TCP 高于要求。
- `subject`、`target`、`dependencies`：公开几何、支撑与容器 owner 依赖、其他物体的裁剪几何。
- `robot`、`physical`、`observation`：机器人反馈、物理状态的证据来源、观测编号与时间。
- `recent_action`：命令位移、实测位移、动作状态和动作 epoch。
- `state_id`、`action_epoch`：单次决策绑定，继续拒绝过期动作。

动态 JSON 仍在每次请求时组装和序列化。固定定义复用减少重复构建，但本轮没有接入慢脑，因此不能把这一改动宣传为已经减少慢脑调用或已经测得模型响应提速。每份输出独立，不覆盖已经发出的状态。

## 几何语义与反馈

原 `subject_from_tcp_robot_base_m` 现在始终表示主体中心相对 TCP 的观测偏移，无法观测时为未知。它不再承载物体到参考中心等不同含义。

现有 `interaction.goal_delta_robot_base_m` 为兼容调用保留，但仅用于语义明确的当前阶段修正，并附 `motion_error_role` 与可观测标记：

- PICK 水平对齐：TCP 到主体顶点的 XY 修正。
- PICK 下降：TCP 到主体中心 XY 及最近抓取高度带边界的修正；与验收共用几何函数。
- PRESS 水平对齐：TCP 到已知按压点的 XY 修正，Z 不参与水平距离。
- TRANSPORT 抬高：主体底部到所需净空的不足量，净空使用源支撑及相关目标高度。
- 相对放置、推动和撤离等关系阶段：没有伪造统一方向向量，使用明确关系、当前条件、公开几何和反馈。

按压动作阶段保留 XY 对齐观测作为持续要求，不把零 XY 误差当作已经按下按钮。释放继续保留有符号的底部到支撑面的距离。

Runtime 阶段检查已完成之后，把该次检查的 outcome、reason、观察编号、稳定计数和具名观测量返回 JEV。投影不会再次执行 verifier，避免重复修改稳定历史。记录同阶段上一动作之前的量用于比较；阶段切换、动作 epoch 不对应或实际重启时不沿用这些比较。比较量不被统一宣称为“进展”，动作完成也不等同于阶段完成。

未知数据用 `null`，未标定的置信度保留 `null`。原视觉字段已有的置信度照实携带，不能因此视为已做现实误差标定。

原 PICK 水平对齐的动作审查与实测进展比较已复用到 PRESS 的点对齐：拒绝预计使当前 XY 距离变差的动作，执行后比较实测误差，不替 JEV 选择另一个动作。这不等同于已经实现所有多条件阶段的通用动作进展审查。

## 推动接近的权限修正

旧验收根据区域中心计算唯一方向及预接触点。新验收检查 TCP 到实际观测 footprint 边界的有符号距离、配置的接触前间距、工具高度、支撑和工具分离。距离计算使用多边形边界，支持旋转后的 footprint。

JEV 根据目标和公开几何选择接近侧；Runtime 不再规定唯一点。最终推动关系、安全间距、稳定观察数保持原含义。接近点位于物体内部、离得过远、高度不符、接触未分离或支撑不成立都不能通过。这一检查仍不等同于全工具体积或整条接近路径的无碰撞证明。

原入碗视觉关系的 0.010 米高度容差已移到 `visual_relation_config.volume_height_tolerance_m`，视觉计算和 JEV 关系说明读取同一具名配置，默认值不变。

## 现实信息边界与未修复项

已核对 Panthera Python 接口：关节和夹爪位置、速度、力矩，以及底层时间戳、模式和故障码有读取字段；没有暴露电流反馈。接口存在不代表真实反馈精度、时间同步或力矩来源已验证，也不能把电机力矩直接视为末端接触力。

本轮为物理状态增加证据来源。当前仿真生成的接触被明确标为 `mujoco_contact_oracle`；抓持和支撑融合分别标为依赖 RGB-D、机器人反馈及该模拟接触信号。它们仍参与当前状态构造和 Runtime 判断。因此当前仿真尚未满足“RGB-D＋机械臂反馈，无接触传感器”的完整信息边界，不能宣称本轮已支持真机闭环。后续必须替换这一状态估计依赖，并以视觉跟随、夹爪受阻及持续观测建立可验证的估计；本轮没有冒充实现该估计器或 RL 力估计模型。

以下前轮审查发现的结构问题仍需要独立修复和验收：完整工具占据与接近路径、低位 PLACE 到下一 PICK 的交接、下降过程中的重新对齐、候选夹持的合法恢复、多物体全局目标复核、ROW 布局编译及视觉遮挡质量。输入语义修复不代表这些问题已经解决。

### 失败揭示的结构缺口

**推开已确认的事实：** 首个接近请求的 TCP 到 footprint 净间距约 0.165 米，要求 0.030±0.010 米；高度修正约 -0.043 米，要求 0±0.012 米。最新诊断明确给出计算公式，仍在上下动作间往返，末次净间距约 0.165 米，没有水平接近。信息存在不代表 JEV 能可靠使用这些信息，不能继续将失败笼统归因于目标字段缺失。

**代码中确认的接口限制：** 当前阶段要求自选接近侧，而 JEV 输出只有下一次原子动作或 BLOCKED；没有显式的接近意图绑定/更新接口。模板复用保存任务定义，不保存已经作出的局部决策。当前进展审查覆盖点对齐和抓取对齐，尚未覆盖推动接近这类多条件阶段。

**尚待验证的判断：** 缺乏持续接近意图及多条件进展反馈可能参与造成动作往返；本轮不能据此证明它们是全部根因。后续设计应明确谁产生并维护局部意图、如何识别无进展、如何请求局部重规划，并继续由 JEV 选择动作。直接指定推开方向、统一强制每步所有误差下降或从失败视频提取路线，会掩盖规划与执行之间的缺口，本轮没有加入这些做法。

**按钮已确认的事实：** 点对齐误差降至约 0.00671 米，小于现有 0.010 米门槛，随后请求向下 0.010 米；实际向下约 0.00689 米，动作末位置误差约 0.00330 米，超过原 0.002 米门槛，在 0.5 秒后超时。执行器对接触动作仍应用同一位移到达条件，Runtime 遇 TIMED_OUT 立即进入恢复流程，没有先区分接触受阻与无接触控制失败。此次输入已能驱动对齐和按压，但按压闭环仍失败。接触是否是未收敛的主因仍需独立诊断；不能仅凭模拟接触标志认定电机堵转或真实受力。本轮未放宽验收、提高增益或使用接触真值越过超时。

本轮完成的是通用输入与阶段反馈层，执行可靠性和现实状态估计尚未完成；十二任务正式复测仍待这些结构缺口处理后开展。
