# 推动 HTTP 400：输入规模与错误记录核查

日期：2026-10-08。在十二任务复测之后，主 agent 与独立协作 agent 分别核对失败请求、成功对照和客户端错误路径。

## 已确认的错误

本批次只有推入区域、推离区域两项收到 HTTP 400，均在预接触通过后的首次建立接触意图请求发生。模型没有返回该意图，接触阶段没有执行新动作；不是 Runtime 接触验收给出的拒绝。

原样重放两份保存的失败意图请求，直接读取服务端正文，两次均为：

```json
{"detail":{"error_type":"max_tokens_exceeded"}}
```

因此这两次重放的具体拒绝类型已确定为服务端 token 预算超限。服务器未返回具体 token 数、计数方式或上限；不能据此发明 64 KB 等字节限制。复测时原请求的响应正文未被客户端保存，两次重放均复现同状态码与明确错误类型，有力支持原失败也是此问题，但不冒称读取到了原响应正文。

两次诊断共发出两次在线请求，均被拒绝；新增成功模型决策 0、新机器人动作 0、新任务回合 0。原十二任务统计保持不变。

## 输入规模的证据

| 保存请求 | 紧凑 UTF-8 JSON 字节数 | 接触几何字段字节数 | 候选 / 每侧动作 |
| --- | ---: | ---: | --- |
| 推入区域 | 74,214 | 55,688 | 四侧 / 七动作 |
| 推离区域 | 74,329 | 55,660 | 四侧 / 七动作 |

接触几何约占整份请求 75%。四个侧面各有当前完整几何，七种动作又各自附完整 `projected_contact_geometry`；完整动作预测几何本身合计约 40.5 KB。这里计算的是 JSON 字节，不能当 token 数。

独立对照发现：本批次最大成功请求为 20,124 字节；旧第二轮成功接触意图请求约 27,215 字节，只包含一个侧面。失败请求可严格 JSON 序列化，没有 NaN；五个 choice 正好为四个接触候选加 blocked。最大嵌套深度与旧成功接触请求相同。没有证据表明 choice 名称或深度是本次独立根因。

代码路径：[四侧投影](../src/jev4mujoco/policies/jev_context.py)、[每动作完整预测几何](../src/jev4mujoco/policies/jev_context.py)、[意图请求](../src/jev4mujoco/policies/jev.py)。前一轮修复撤销了未到达侧面的错误继承，合法开放当前四侧候选；输入投影没有同时处理候选增加后的规模。不能为缩小输入重新强制只保留未经实现核验的旧侧面。

## 确认的框架问题与修复边界

一是模型输入投影缺少适应模型预算的结构：候选选择把多侧、多动作的完整几何逐项展开。Runtime 的详尽内部证据与模型本次选择所需的决策摘要应分开。

二是客户端错误可观测性不足：[TypeSafeClient](../src/jev4mujoco/policies/typesafe_client.py) 在非 200 响应中只保存状态码和通用 error，丢弃正文和请求标识。HTTP 400 原本可以解释，日志却把它变成了难以定位的错误。

下一轮最小方案应同时处理这两处：保留四侧候选、有限侧面身份、当前距离/误差/重叠/未知状态、简洁动作预测，以及阶段条件、约束证据和状态绑定；几何与不随动作改变的定义共享一次，避免重复展开每个预测的完整几何。输入预算要有明确失败诊断，不能靠截断 JSON 或删除阶段目标解决。错误记录应保留有长度边界且不包含凭据的响应正文，以及服务端提供的请求标识。

本轮尚未验证压缩后的请求、模型选择或完整推动执行。具体模型上限仍未知；输入变小能否通过、保留摘要能否支持正确决策，需后续正反例与保存输入对照。两个接口问题也不能解释其余九项未通过。

协作 agent 的离线精简对照：仅移除每动作完整 `projected_contact_geometry`，保留四侧当前几何、动作位移/预测误差/预测进展/来源/假设与 null 后，两请求降至 32,847 / 32,984 字节，约减少 56%。这会减少逐部件未来间距与重叠亏量等预测细节，应作为有明确语义边界的输入契约调整审查，不能宣称完全没有信息变化。没有向服务端发送精简请求，也未实施生产修改。
