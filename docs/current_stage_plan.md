# 当前架构与实现边界

更新于 2026-10-13。本文描述活动实现；历史修复过程已移出项目，恢复位置见[清理记录](cleanup_20261013.md)。

当前已有共享抓取、搬运、放置、推动和按压闭环，但仍是给定计划下的执行框架。高层 LLM 尚未接入，十二类预设任务的覆盖不能等同于任意指令的通用规划能力。

## 当前执行链与职责

预设指令 + 首帧 `VisualSceneV1` → `TaskPlanV1` → `CapabilityProgramV1` → Runtime 激活阶段 → JEV 局部意图/原子动作 → Runtime 审查 → 执行器 → 新观测与机器人反馈 → Runtime 核验。

| 层 | 当前职责 | 主要入口 |
| --- | --- | --- |
| 视觉 | 同一结构描述实体、区域、关系及证据来源；每次观测产生新实例 | [视觉契约](../src/jev4mujoco/contracts/visual_scene.py)、[RGB-D 适配器](../src/jev4mujoco/perception/fixed_rgbd.py) |
| 任务规划 | 预设构建器根据指令模板和首帧绑定主体与目标，描述目标关系及完成契约 | [任务契约](../src/jev4mujoco/contracts/task_plan.py)、[预设](../src/jev4mujoco/planning/presets.py) |
| 编译 | 校验计划并展开为参数化能力，不生成具体动作轨迹 | [编译器](../src/jev4mujoco/planning/compiler.py)、[能力模板](../src/jev4mujoco/planning/capabilities.py) |
| JEV / System1 | 在当前阶段权限内选择动作；两层模式先选择并保留局部意图，再根据新观测选择动作 | [策略](../src/jev4mujoco/policies/jev.py)、[上下文](../src/jev4mujoco/policies/jev_context.py) |
| Runtime | 状态融合、意图有效性与进展、动作绑定审查、阶段转换、超时、恢复预算及公开完成核验 | [循环](../src/jev4mujoco/runtime/loop.py)、[能力运行时](../src/jev4mujoco/runtime/capability_runtime.py)、[验证器](../src/jev4mujoco/runtime/verifier.py) |
| 执行器 | 接受获准动作，连续伺服，报告实测结果与位置收敛异常 | [执行器](../src/jev4mujoco/simulation/executor.py)、[后端](../src/jev4mujoco/simulation/backend.py) |
| 独立裁判 | 回合结束后使用隐藏仿真真值核对任务效果，不向在线控制回流 | [评价](../src/jev4mujoco/experiments/evaluation.py) |

未来 System2 的自然语言理解、视觉绑定和策略重规划仍是设计方向。当前 JEV 的局部重规划只调整局部意图，不能改写任务或能力拓扑；模型不能直接宣布阶段或任务完成。

## 十二类任务复用五类能力

| 实验选项 | 任务 | 能力组合 |
| --- | --- | --- |
| `pick` | 抓取 | `pick` |
| `pick_and_place` | 抓放 | `pick → transport → place(goal)` |
| `sort` | 分类 | 对绑定对象重复抓放到对应区域 |
| `clear` | 清理 | 对初始区域对象重复抓放 |
| `relative` | 相对放置 | 抓放到相对关系目标 |
| `bowl` | 入碗 | 抓放到 `INSIDE` 目标 |
| `arrange` | 排列 | 对绑定对象重复抓放到指定槽位 |
| `stack` | 堆叠 | 抓放到 `ON_SURFACE` 目标 |
| `push_to_region` | 推动入区 | `surface_push(IN_REGION)` |
| `push_aside` | 推动移出 | 对绑定对象执行 `surface_push(CLEAR_OF_REGION)` |
| `press` | 按压 | `press`，核验按压事件 |
| `ordered` | 顺序组合 | 按阶段顺序组合以上能力 |

目标描述关系、引用和期望值；具体接触边、方向、准备位置和动作次数由局部闭环决定。能力具有预定义阶段，Runtime 控制转换；抓取包含准备、对齐、下降、闭合、探测和验证。容差、稳定观测数与预算来自配置，不由模型临时放宽。

排列当前按用户确认的相机画面左到右红—黄—蓝，将首帧颜色绑定到三个同色圆垫的唯一槽位。Runtime 重核全部当前槽位与稳定观测，独立裁判核对实际圆垫支撑。各场景有对应 XML 与 RGB-D 配置，公共机械臂和桌面配置在 `scenes/common.xml`。

## 已实现的闭环与剩余缺口

- 共用状态与证据契约区分当前观测、历史来源、估计和未知；动作绑定状态 ID、epoch、能力实例和阶段。
- 两层 JEV 支持持续意图、实际进展检查、失效反馈及有限局部重规划。放置支持关系恢复、水平准备、释放后工具退出、观测恢复及稳定结果分类。
- 任务入口与编译仍覆盖封闭的十二类。顺序组合在首帧展开；尚无高层持续重规划或自动重新绑定机制。
- 多对象整体验收仍包含场景类的补充逻辑，尚未全部统一为计划驱动的完成契约；`avoid_other_objects` 的完整验证尚未支持。
- 已有 `observe`、`retry_pick`、`retry_capability`、`stop` 恢复入口与预算。恢复按当前公开证据重启当前能力或抓放链，保留现场与其他对象已完成能力；尚未形成统一恢复策略，也不保证后续运动不会扰动已完成对象。
- 执行器内部连续伺服，但每个原子动作仍同步等待模型。等待 API 时仿真不继续推进，尚未验证现实时间下的持续观测、过期决策拒绝和可中断交接。

## 现实输入与证据边界

在线可用输入为 RGB-D、关节位置/速度、估计力矩、控制指令、夹爪位置与校准参数。接触、持有与支撑由公开视觉及机器人运动响应估计；几何邻近不是物理接触证明，估计力矩不是已校准的外部力反馈。

当前仿真使用理想实例掩码及配置的类别/颜色语义，几何由 RGB-D 重建。真实分割、识别、跟踪尚待替换验证；SAM 3 尚未安装或完成推理测试。隐藏物体位姿、接触与支撑真值仅供训练标签、奖励和独立裁判。硬件细节以[真实反馈契约](real_robot_feedback_contract.md)为准。
